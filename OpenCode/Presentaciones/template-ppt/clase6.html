La idea

Tool, skill, MCP y plugin no son lo mismo

Cuando hablamos de “darle capacidades” a un agente, solemos mezclar cuatro cosas distintas. Conviene separarlas porque cada una resuelve un problema diferente.

  • Tool. Una acción puntual que el agente puede invocar: leer un archivo, correr Python, consultar una base.
  • Skill. Un paquete de saber hacer: instrucciones, scripts, criterios, plantillas y procedimiento.
  • MCP. El enchufe estándar que conecta al agente con sistemas externos sin rehacer cada integración desde cero.
  • Plugin. Una extensión empaquetada para una plataforma concreta, con su propia distribución, permisos o interfaz.
03 / 10
Tool

La tool es la acción mínima

Una tool hace una cosa concreta. No “sabe” resolver una tarea compleja: ejecuta una operación. El razonamiento lo pone el agente.

  • Qué trae. Nombre, descripción, parámetros de entrada, resultado y límites de uso.
  • Para qué sirve. Ejecutar una acción puntual: buscar, leer, consultar, transformar, exportar.
  • La clave. La tool actúa; no decide el método general de trabajo.
tool conceptual
tool: buscar_en_sqlite
input: { consulta: "SELECT * FROM notas" }
output: filas de la base
04 / 10
Skill

La skill enseña un procedimiento

Una skill no es sólo una función. Es una manera de trabajar bien una tarea que se repite: trae instrucciones, ejemplos, validadores y usa las tools que hagan falta.

  • Qué puede incluir. Instrucciones, scripts auxiliares, plantillas, ejemplos, esquemas JSON, validadores y advertencias.
  • Para qué sirve. Encapsular un método experto para que el agente no improvise cada vez.
  • La diferencia. Tool = “ejecutá esto”. Skill = “trabajá así y usá las tools necesarias”.

├── ejemplos/

05 / 10
Conexión y empaquetado

MCP conecta; el plugin empaqueta

MCP no es una tool ni una skill: es el protocolo que deja conectar al agente con sistemas externos. Un plugin, en cambio, es una extensión pensada para una plataforma concreta.

MCP

Es un estándar abierto. Expone tools, recursos y prompts de forma interoperable. La misma integración puede servir para distintos clientes compatibles.

  • Servidor MCP de GitHub
  • Servidor MCP de SQLite
  • Servidor MCP de Playwright

Plugin

Es una extensión instalable dentro de una plataforma específica. Su sentido depende del ecosistema donde vive: ChatGPT, Codex, un IDE o cualquier app que soporte extensiones.

  • App o conector de ChatGPT
  • Plugin de un IDE
  • Extensión específica de una plataforma

Cuadro resumen

Cuatro conceptos, cuatro funciones

Si hubiera que quedarse con una sola regla práctica, sería esta: la skill le dice al agente cómo trabajar; la tool le permite actuar; MCP le da un enchufe estándar; el plugin empaqueta eso dentro de una plataforma.

TOOL

Acción puntual

Qué es: una función invocable.
Sirve para: ejecutar una operación concreta.
Ejemplo: leer archivo, correr Python, consultar SQLite.

SKILL

Saber hacer

Qué es: un paquete de procedimiento experto.
Sirve para: repetir bien una tarea compleja.
Ejemplo: skill para PDF, slides o scraping.

MCP

Protocolo

Qué es: un estándar de conexión.
Sirve para: enchufar sistemas externos al agente.
Ejemplo: GitHub, Playwright, filesystem, SQLite.

PLUGIN

Paquete instalable

Qué es: una extensión de plataforma.
Sirve para: distribuir una capacidad con permisos e integración.
Ejemplo: app de ChatGPT, extensión de IDE, plugin de Codex.

Elección

Mostrar datos es tomar una decisión

Una visualización no es decoración. Ordena la lectura, destaca relaciones y también puede ocultar problemas.

  • El gráfico debe responder una pregunta concreta.
  • No todo dato necesita visualización.
  • La escala, el orden y el color son decisiones interpretativas.
  • La claridad vale más que el efecto visual.
08 / 10
Tipos

Elegir el gráfico según la pregunta

La IA puede sugerir gráficos, pero conviene saber cuándo cada tipo tiene sentido.

  • Barras: comparar categorías.
  • Series temporales: observar cambios en el tiempo.
  • Nubes de palabras: exploración inicial, no prueba concluyente.
  • Dispersión: explorar relaciones entre variables.
09 / 10
Prompt

Cómo pedir un gráfico útil

Un buen pedido de visualización incluye datos, objetivo, variable principal, formato y criterio estético.

  • Indicar columnas disponibles y significado de cada una.
  • Explicar qué comparación se quiere observar.
  • Pedir etiquetas legibles y título interpretativo.
  • Solicitar exportación en PNG/SVG y versión editable.
10 / 10
Interpretación

Del gráfico bonito al gráfico correcto

La IA puede producir una visualización visualmente atractiva pero metodológicamente pobre. Hay que revisar proporciones, escalas y etiquetas.

  • Verificar que no falten valores.
  • Revisar que el eje no distorsione la comparación.
  • Evitar colores que sugieran jerarquías falsas.
  • Acompañar el gráfico con una lectura breve.
