Base

Un script es una secuencia

Un script ordena acciones: leer datos, transformarlos y producir una salida. Entender esa estructura alcanza para empezar a trabajar con IA de forma responsable.

  • Entrada: archivos, carpetas, tablas o texto.
  • Proceso: instrucciones que modifican, cuentan, filtran o clasifican.
  • Salida: CSV, gráfico, texto limpio o reporte.
03 / 10
Entornos

Dónde ejecutar sin complicarse

La elección del entorno debe reducir fricción, no aumentarla. En este curso priorizamos OpenCode porque permite pedir, revisar, documentar y ejecutar scripts desde un mismo espacio de trabajo.

  • OpenCode: opción principal. Podemos pedirle que escriba y documente un script, que lo ejecute en terminal o que nos dé el comando exacto para correrlo.
  • VS Code: alternativa sólida cuando queremos un editor tradicional con extensiones y control manual.
  • Google Colab / Jupyter: útiles para notebooks, exploración paso a paso y pruebas rápidas con datos.
  • Positron: alternativa potente para análisis de datos y flujos cercanos a RStudio.

Vocabulario

Variables, archivos y carpetas

No hace falta dominar toda la programación para entender lo mínimo necesario.

  • Una variable guarda un valor con nombre.
  • Una ruta indica dónde está un archivo.
  • Una función agrupa instrucciones reutilizables.
  • Un error es información: dice dónde falló el proceso.
05 / 10
Jerarquía

System prompt y prompt de usuario no son lo mismo

Cuando usamos un agente, no todo lo que lo guía viene del mensaje que escribimos. Hay instrucciones de fondo —más estables y con mayor prioridad— que definen identidad, reglas, herramientas y procedimientos.

  • System prompt: instrucciones de nivel superior. Define rol, límites, estilo, permisos y reglas de trabajo.
  • Prompt de usuario: el pedido situado. Dice qué queremos hacer ahora, con qué datos y con qué objetivo.
  • Módulos de sistema: archivos y definiciones que se cargan como partes del contexto del agente.
  • Regla práctica: el usuario dirige la tarea; el sistema define el marco seguro para ejecutarla.
06 / 10
Roles

Agente y subagente no son el mismo rol

Un agente puede sostener la conversación principal, interpretar el objetivo y decidir el rumbo. Un subagente es una unidad más acotada: recibe una misión concreta, trabaja con contexto limitado y devuelve un resultado.

  • Agente: coordina, conversa, prioriza, decide cuándo pedir aclaración y cuándo delegar.
  • Subagente: ejecuta una fase o tarea específica: explorar, diseñar, aplicar cambios, verificar.
  • Menos contexto, más foco: el subagente no necesita saber todo; necesita saber lo justo para su encargo.
  • Resultado: el subagente devuelve hallazgos, cambios o verificación; el agente integra y decide el siguiente paso.
07 / 10
Quién

AGENTS.md: quién es el agente

AGENTS.md —o AGENTES.md si lo nombramos en español— funciona como un módulo de system prompt. No describe una tarea puntual: describe la identidad operativa del agente dentro de un proyecto.

  • Rol: qué tipo de asistente es —docente, revisor, programador, orquestador, investigador.
  • Criterios: cómo debe decidir, qué debe priorizar y cuándo debe pedir aclaración.
  • Estilo: tono, idioma, nivel de detalle, forma de explicar y de corregir.
  • Límites: qué no debe hacer, qué requiere permiso y qué debe verificar antes de afirmar.
08 / 10
Cómo

SKILLS.md: cómo se hace una tarea

Una skill no es “un prompt guardado”. Es conocimiento operativo empaquetado: cuándo usarlo, qué pasos seguir, qué revisar y qué recursos aplicar. En muchos entornos aparece como varios archivos SKILL.md, uno por capacidad.

  • Disparadores: señales que indican cuándo cargar esa skill.
  • Procedimiento: pasos, checklist, criterios de calidad y advertencias.
  • Recursos: plantillas, ejemplos, convenciones o scripts auxiliares.
  • Consistencia: distintos agentes pueden trabajar con el mismo método, no improvisar cada vez.
09 / 10
Con qué

Tools: con qué herramientas actúa

Las tools no son deseos del modelo: son funciones autorizadas por el entorno. Entran al contexto del agente como contratos de acción: qué puede llamar, con qué parámetros y qué resultado recibirá.

  • Leer y modificar archivos, buscar en el proyecto, ejecutar comandos o abrir un navegador.
  • Consultar servicios mediante MCP: documentación, GitHub, Zotero, Figma, Playwright.
  • Permisos: el host valida antes de ejecutar. El modelo solicita; la herramienta actúa.
  • Salida estructurada: la tool devuelve datos, logs o diffs que el agente usa para decidir el siguiente paso.

Taller

Un prompt simple para empezar

La práctica ahora es pedir un código claro, documentado y fácil de leer: tokenizar un texto y construir una nube de palabras en Python.

"Necesito un código en Python, bien documentado y fácil de entender, que tome un texto, lo tokenice y genere una nube de palabras. Quiero que expliques cada paso en comentarios o docstrings, que uses librerías comunes si hace falta, y que al final me indiques cómo ejecutarlo en mi computadora. Si hay más de una forma de hacerlo, elige la más simple y clara para alguien que recién empieza."
  • Entrada: un texto simple o un archivo de texto.
  • Salida: una nube de palabras legible y un script comentado.
  • Pedido extra: que explique dependencias y comando de ejecución.
  • Objetivo pedagógico: entender el código, no solo copiarlo.
